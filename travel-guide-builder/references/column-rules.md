# 九列填充规则（用户原始规格，逐条照做）

以下 A-I 列规则来自用户对自己模板表的明确定义，**不要自行简化**。

| 列 | 名称 | 规则 |
|---|---|---|
| **A** | 日期 | `DAY<第几天>` 换行后接日期，格式 `月/日`。例：`DAY1\n10/1`。可加星期提高可读性（`DAY1\n10/1 周四`） |
| **B** | 大交通 | **只写起点城市和终点城市**。起点＝当天早上醒来时的住宿所在城市；终点＝当晚入住酒店所在城市。格式 `深圳 ✈ 贵阳` / `贵阳 → 安顺·黄果树`。可换行加一行括号注明住宿城市 |
| **C** | 简要行程 | 列出当天**所有大景点 + 城市**，并写清城市/景区之间的**通勤方式与时长**。每个地点单独一行，行尾接 `→`。顺序必须严格按箭头方向推进，不能错序 |
| **D** | 详细行程 | 把 C 列的每个大景点拆成更细的说明：内含哪些小景点/小项目、小景点之间怎么走、大景点内要等多久的车。**每个大景点单独成行，用 `【】` 包裹并标红加粗**，换行后接说明。一个大景点写完后**空一行**再写下一个。**机场/车站/中转站等过境节点写 `〔交通〕`，特产采购等事务节点写 `〔事项〕`**（见下节） |
| **E** | 机位 | 也按大景点组织，`【】` 标红加粗 + 换行 + 每个机位点。要写清**最佳时段/光线方向**，纯列名字没用。**非景点块没有「机位」这个概念，不要给它们写机位块** |
| **F** | 餐饮 | 早/午/晚各自的本地饮品与美食特色，**再加当天所有城市的总推荐**。每个推荐必须括号注明**属于哪个城市**，便于定位。用 🌅🍜🍲🥤 等符号分节 |
| **G** | 酒店 | 携程拿到的**真实报价 + 店名**，再写小红书推荐的住宿店铺和价格。**酒店必须在当天行程的终点城市/县城**。固定带一句 `⚠️ 最终住宿后续再来确定` |
| **H** | 备注（穿衣+避坑） | 按大景点组织，`【】` 标红加粗 + 换行。每个景点写：**① 当日适配的穿衣搭配建议（季节性 + 色彩搭配，要说清楚为什么这么搭）② 避坑点**，覆盖消费陷阱 / 路线误区 / 天气不适应三类。所有景点写完后，视情况补一段**当日总备注** |
| **I** | 注意事项 | 按大景点组织，`【】` 标红加粗 + 换行。写**预约 / 买票 / 行程**相关的硬信息（提前几天抢票、票价构成、开放时间、营业截止）。所有景点写完后，视情况补一段**当日总注意事项** |

## ⚠️ 非景点块用 `〔交通〕` / `〔事项〕`，不是 `【】`

行程表里除了景区，还有**两类「不是景点、却各自占一整个块」**的东西：

| 类别 | 包含 | 标记 |
|---|---|---|
| **交通枢纽** | 机场、火车站、高铁站、动车站、城际站、汽车站、客运站、码头、航站楼、租车取车点 / 还车点 / 提车点，以及带「（中转站）」标注的节点 | `〔交通〕节点名` |
| **事务节点** | 特产采购、采购 / 采买 / 购物、手信 / 伴手礼 / 纪念品 | `〔事项〕节点名` |

它们没有「景点详细行程」「机位」「美景实拍」。用 `【】` 写它们，
下游会把它们当成大景点，生成完整的景点页（详细 + 美景机位），非常荒唐 ——
「特产采购」会白占一个景点页，机场连「候机厅落地窗」都成了机位。

```
✅ 正确
【贵阳·黔灵山公园】
市区 5A 级免费公园，核心看点是半野生猕猴群…

〔交通〕贵阳·龙洞堡机场
贵阳唯一的民用机场，落地走 T2 到达层出口。取车必做：绕车录像一圈…

〔事项〕贵阳市区 · 特产采购
最后半天留给买手信和吃最后一顿贵州菜。采购点：二七路小吃街…

❌ 错误（机场 / 采购被当成景点）
【贵阳·龙洞堡机场】
贵阳唯一的民用机场…
【贵阳市区 · 特产采购】
最后半天留给买手信…
```

D / E / H / I 四列通用。`〔交通〕` / `〔事项〕` 块在输出里的去向：

- D 正文 → 当日**注意事项**（取车/还车流程、中转补货、采购要点）
- E 机位 → **丢弃**
- H 穿搭 → 当日**穿搭**；H 避坑 → 当日**备注**（起 `🚉 / 🛍 节点名` 小标题）
- I 内容 → 当日**注意事项**；「提前下单/预约」类仍进**出发前必看**

> 双重保险：即使误写成 `【】`，只要名字命中关键词（或正文以「（中转站）」开头），
> 解析脚本也会自动纠正。但**源表写对**才是根本。
>
> 共享模块：`scripts/nonspot_rules.py`；批量改写源表：`scripts/fix_nonspot_xlsx.py`。

## 通用写作约束

- **大量使用 icon / 表情 / 符号**。分节用 `🌅🍜🍲🥤🚗🚶🚌✈🏨📕⚠️👕📌`；避坑条目用带圈数字 `❶❷❸`；
  必做事项用 `①②③`；小贴士穿插 `💡🔥💧`。
- **深浅对比色 + 加粗**，信息要能扫读，不要整块密密麻麻的纯文字。
- **信息必须可以照着执行**：票价要拆成「门票 + 观光车 + 扶梯」而不是一个总数；
  时长要写实（「步行栈道 40min」而非「走一会儿」）；通勤要写清方式（「🚌观光车 20min」）。
- **同一个景点在不同列必须同名**（如「黄果树」不能被写成「黄樹果」），生成后必须做一致性扫描。
- 不要编造素材里没有出现过的店名或票价，宁可写「待核实」。
