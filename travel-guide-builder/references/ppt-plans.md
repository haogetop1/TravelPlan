# PPT 两套方案：详细版（方案一）/ 简洁版（方案二）

同一个 `攻略.xlsx` 出两套 PPT，**共用前 4 页与后 2 页**，只有中间的逐日页面不同。
用户常见的原话是：

> 方案一（详细版）信息全但要翻很久；方案二（简洁版）一天两页，发给同行的人看。

---

## 1. 页序（硬约定）

| # | 方案一 · 详细版 | 方案二 · 简洁版 |
|---|---|---|
| 01 | 封面：`某目的地 X 天 Y 晚 自驾旅游攻略` | 同左 —— **完全共用** |
| 02 | 总行程：全部行 C 列骨架 + **总路线地图** | 同左 —— 完全共用 |
| 03 | 人均预算 | 同左 —— 完全共用 |
| 04 | 出发前必看 | 同左 —— 完全共用 |
| 05… | 逐日：<br>① 当天行程页（B+C 列 + 当天城市地图）<br>② 每个大景点 2 页（详细页 + 美景机位页）<br>③ 当天收尾页（总备注 + 总注意事项 + 穿搭） | 逐日 × N 天，**每天 2 页**：<br>① 今日行程（时间轴 + 推荐机位 + 避坑注意事项）<br>② 今日吃住（三餐 + 特色美食 + 住宿推荐 + 备注穿搭） |
| 次尾页 | **物品清单** | 同左 —— 完全共用 |
| 尾页 | **结束祝福**（「祝大家旅行顺利」） | 同左 —— 完全共用 |

> **次尾页物品清单 + 尾页结束祝福** 是用户明确要求的收尾（原话 3.7 / 3.8），
> **两套方案都必须有**。方案一曾经只有物品清单、没有结束页，属于缺页。

页数参考（贵州 7 天 6 晚 · 12 个大景点）：
- 方案一 = 4（共用头）+ 7 天 ×(1 行程 + 12 景点×2 + 1 收尾) + 2（共用尾） = **44 页**
- 方案二 = 4 + 7 天 × 2 + 2 = **20 页**

## 2. 共用的实现方式（别复制粘贴）

```
slides_common.py                  ← 骨架 + 共用页 + 渲染导出管线（两个 build 都 import）
roadbook/templates/
  _ppt_base.css.j2                ← 共用 CSS 令牌（颜色 / 卡片 / 时间轴 / 表格 / 照片栅格）
  _ppt_shared_pages.j2            ← 共用 6 页的 HTML 块（封面/总行程/预算/必看/物品清单/结束）
  ppt_detail.html.j2              ← 方案一：include 上面两个 + 自己的 4 种逐日页
  ppt_simple.html.j2              ← 方案二：include 上面两个 + 自己的 2 种逐日页
build_ppt_detail.py               ← 方案一构建器
build_ppt_simple.py               ← 方案二构建器
```

共用页由 `slides_common.head_slides()` / `tail_slides()` 提供，**两个构建器都调用同一个函数**，
这样两套 PPT 的封面文案、预算表、物品清单**逐字节一致**，不会出现「方案一说 950km、
方案二说 900km」这种互相打脸。

> ⚠️ **Jinja2 要支持 `{% include %}` 必须用 `Environment(loader=FileSystemLoader(dir))`。**
> `Template(open(f).read())` 这种写法**不支持 include**，会直接报 `TemplateSyntaxError`。
> `slides_common.render_and_export()` 里已经切成 Environment 版本。

## 3. 构建

```bash
PY=<venv>/python.exe

# 数据链（改了 xlsx 或抽取器就必须重跑，否则拿旧 JSON 拍平 → 内容重复）
$PY extract_xlsx_slides.py      # xlsx → roadbook/_raw/detail/slides.json
$PY allocate_photos.py          # 按「天+景点名关键词」分配照片 → photo_map.json

# 两套 PPT
$PY build_ppt_detail.py         # 方案一 → 贵州..._详细版.pptx   （截图前缀 d_）
$PY build_ppt_simple.py         # 方案二 → 贵州..._简洁版.pptx   （截图前缀 c_）

# 自检
$PY check_detail_overflow.py            # 方案一：卡片内部裁剪 + 页底溢出
$PY diag_simple_overflow.py             # 方案二：逐卡「内容高度 / 可视高度 / 裁剪量」
$PY make_detail_sheet.py                # 方案一验收联络表
$PY make_simple_sheet.py                # 方案二验收联络表
```

截图帧放在同一个 `_raw/detail/` 下，靠**文件名前缀区分**（方案一 `d_`、方案二 `c_`），
互不覆盖。

## 4. 版式硬约束（这一节是踩坑换来的，别改回去）

### 4.1 一页最多装多少：先量，别猜

渲染管线里有一道**自动缩排兜底**（`AUTOFIT_JS`）：卡片内容装不下时按 0.5px 步长收字号，
下限 12px，并把缩排后的 DOM 导出成 `*_fitted.html` 供复检。

但它只是**兜底**。条目多到 12px 还装不下，内容就会被 `overflow:hidden` **静默裁掉** ——
构建日志里那句 `⚠️ 仍差 Npx，需人工删减内容` 就是在喊这件事，**必须处理，不能放过**。

正确做法是先量真实内容高度再排版式：

```bash
DIAG_HTML=<绝对路径>/simple.html $PY diag_simple_overflow.py
```

（指定未缩排的 `simple.html` 才能拿到**基准字号下的真实内容高度**；
量 `*_fitted.html` 拿到的是已经缩过字号的高度，会低估。）

### 4.2 flex 的两条铁律

**坑 A —— `flex:none` 的卡片会把 `flex:1` 的兄弟挤成 2px。**
方案二第一版把「推荐机位」设 `flex:1`、「备注穿搭 / 避坑注意事项」设 `flex:none`，
结果那两张长卡片把机位压到 **2px 高**，机位内容整段被裁（最多裁 306px）。

**坑 B —— 兄弟卡片不要写死配比，要用内容自适应。**
写成 `flex:5` / `flex:10`（基准 0）时是**固定切分**，可实际内容逐日差异极大：

| 天 | 推荐机位 | 避坑注意事项 |
|---|---|---|
| DAY1 | 308px | 438px |
| DAY2 | **497px** | 116px |
| DAY7 | 51px | **623px** |

写死 5:10 就会让「机位多、避坑少」的那天把机位裁掉。
改成 **`flex:1 1 auto`（基准 = 内容高度）**，两张卡按内容分摊富余高度，
实测两者合计最多 746px < 830px 可用，**全天都装得下、无需缩字号**。

对「内容少但说明性强」的那张（推荐机位）再加 `flex-shrink:0`，
防止被按比例收缩时又裁掉一整段：

```css
.dstack .r1{flex:1 0 auto;...}   /* 推荐机位：不参与收缩 */
.dstack .r2{flex:1 1 auto;...}   /* 避坑注意事项：由它承担伸缩 */
```

### 4.3 时间轴必须独占一条整页高的列

「今日行程规划」最多 18 步 ≈ **700-760px**。
塞进上下两段（各 ~420px）必被裁；`column-count:2` 也救不了 ——
栏宽减半后每步折成两行，总高度几乎不变。**只有整页高的列装得下。**

### 4.4 `column-count` 只在「宽栏」上降高度

通栏 + 双栏是把高度压一半的有效手段，**前提是每一栏仍然足够宽**：

- 栏宽 ≈ 880px（46 字/行）→ 一条目一行 → 高度真的减半 ✅
- 栏宽 ≈ 400px（21 字/行）→ 一条目折成两行 → 高度不变甚至更差 ❌

所以「避坑注意事项」这种长文本要点：**通栏放，然后 `column-count:2`**；
不要把它塞进窄列里再分栏。

### 4.5 方案二的最终栅格（照这个抄）

```
dayplan 今日行程
  .dgrid  grid-template-columns: 42% 1fr   height:100%
    ├ 左（整页高 848px）：今日行程规划（编号时间轴）
    └ 右 .dstack（上下分，flex:1 0 auto / flex:1 1 auto）
        ├ 推荐机位
        └ 避坑 · 注意事项   ← card-b 加 .cw2（通栏双栏）

daystay 今日吃住
  .sstack  flex column
    ├ 上排 64%（.stop）
    │   ├ 今日三餐
    │   ├ 特色美食 · 饮品
    │   └ 住宿推荐 · 报价参考      ← 最高，DAY5 实测 458px，故上排给 64%（58% 会裁 49px）
    └ 下排 通栏：备注 · 穿搭        ← card-b 加 .cw2
```

### 4.6 跨块去重（同一句别渲染两遍）

同一句提示常**同时出现在当日总备注（H 列）和某个非景点块（🚉/🛍）里**：

> DAY7「白天短袖 + 薄外套；飞机上空调足…」既是当日穿搭，又是特产采购节点的穿搭。

只做「块内去重」不够，**必须跨块去重**（`slides_common.dedup_blocks()`）。
实测 DAY7 的备注·穿搭从 12 行降到 3 行、重复归零。

方案一还有一处同源问题：节点块里把穿搭写成 `穿搭：xxx` 塞进「当天总备注」，
和下方「当天穿搭建议」列**重复**。正确做法是节点块**只取 `avoid`**，
穿搭统一由「当天穿搭建议」列呈现。

## 6. 踩坑表

| 坑 | 现象 | 修法 |
|---|---|---|
| `flex:none` 挤死 `flex:1` 兄弟 | 卡片被压成 2px，内容整段消失 | 长卡片用 `flex:1 1 auto`；短卡片 `flex-shrink:0` |
| 兄弟卡写死 `flex:5/10` | 内容多的那天被裁 | 改 `flex:1 1 auto`，让基准 = 内容高度 |
| `column-count` 用在窄列 | 高度不降反升 | 只在通栏（≥800px/栏）上用 |
| 时间轴塞进半高区 | 18 步必被裁 | 时间轴独占整页高的列 |
| 只做块内去重 | 同句出现两遍 | `dedup_blocks()` 跨块去重 |
| `Template(str)` 用 `{% include %}` | `TemplateSyntaxError` | 换 `Environment(FileSystemLoader)` |
| 构建脚本无脑 `rm d_*.png` | 被宿主的**批量删除保护**拦下，构建进程直接终止（本轮删到第 50 个文件时触发） | 只删「序号 > 本次页数」的超范围旧帧 |
| 对同一文件并行发两个 Edit | 后写覆盖前写，改动静默丢失 | 同一文件的多次编辑**串行**下发 |
| 拿旧 `slides.json` 直接构建 | 页面内容重复（新旧两版一起渲染） | 改抽取器后必须重跑 `extract_xlsx_slides.py` |
| 用 grep 数 emoji | Git Bash 下匹配失败，误判「没有」 | 用 Python `str.count()` |
| 对整页图片版 PPT 做文字扫描 | 永远查不到内容，得出「没有该页」的错误结论 | 校验渲染源 HTML + 截图 |
