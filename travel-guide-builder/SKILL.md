# 旅游攻略表格生成

## 何时用

用户要一份**能直接照着出行的行程表**，而不是一篇散文式攻略。典型信号：

- 提供了参考模板表格链接（腾讯文档 / Excel），要求「参考这个格式」
- 指定了天数、人数、预算档次、交通方式、出发地目的地
- 要求给出**人均总预算**
- 要求注明价格真实来源（携程 / 神州 / 官方票价）

## ⚠️ 「非景点块」不是景点（贯穿 xlsx → HTML → PPT 的硬约束）

行程表里除了**景区**，还混着两类「不是景点、却各自占一整个块」的东西：

| 类别 | 包含 | 图标 |
|---|---|---|
| **交通枢纽** | 机场、火车站、高铁站、动车站、城际站、汽车站、客运站、码头、航站楼、租车取车点 / 还车点 / 提车点，以及标注「（中转站）」的过境节点 | 🚉 |
| **事务节点** | 特产采购、采购 / 采买 / 购物、手信 / 伴手礼 / 纪念品 | 🛍 |

它们**没有**「景点详细行程」「最佳机位」「美景实拍」这些概念。
一旦被当成大景点，会在整条链路上被逐级放大成荒唐的结果：

> 龙洞堡机场 → 拿到「景点详细页 + 小红书美景照页 + 最佳机位」
> → 甚至连「候机厅落地窗」都成了机位；
> 特产采购 → 也白占一个景点页 + 一页「机位」。

**两类都必须不进景点列表**，内容降级为当日「🚉 交通节点 / 🛍 事务节点」，
并入当天的备注与注意事项。

### 源头怎么标（xlsx）

| 块类型 | 标记 | 后果 |
|---|---|---|
| 景点 | `【景点名】` | 进景点列表，占景点页（详细 + 美景机位） |
| 交通枢纽 | `〔交通〕节点名` | **不进景点列表**，降级为当日「🚉 交通节点」 |
| 事务节点 | `〔事项〕节点名` | **不进景点列表**，降级为当日「🛍 事务节点」 |

D / E / H / I 四列都适用。判定有**双重保险**：即使写成 `【】`，
只要名字命中关键词（或正文以「（中转站）」开头）也会被自动纠正。
**只有 `【】` 才可能是大景点。**

### 各列怎么处理

| 列 | 对非景点块的处理 |
|---|---|
| **D** 详细行程 | 不生成景点块；正文（取车/还车流程、中转补货、采购要点）并入**当日注意事项** |
| **E** 机位 | **整块丢弃**（机场/车站/采购点没有「机位」这个概念） |
| **H** 备注 | 穿搭 → 当日穿搭；避坑 → 当日备注（以 `🚉/🛍 节点名` 起小标题） |
| **I** 注意事项 | 内容并入**当日注意事项**；其中「提前下单/预约」类仍计入**出发前必看** |

### 四条实现要点（踩过的坑）

> 共享模块直接用 `scripts/nonspot_rules.py`
> （`kind_of` / `is_nonspot` / `split_blocks` / `remark_in_text` / `KIND_ICON`），
> 批量改写源表用 `scripts/fix_nonspot_xlsx.py`（先 dry-run，确认后加 `--apply`）。
> **HTML 链路与 PPT 链路必须引用同一份**，不要各写一套正则。
> （旧的 `transit_rules.py` 只管交通枢纽，已被 `nonspot_rules.py` 取代。）

1. **别用 `d{天}s{序号}` 做键。** 剔除一个非景点就会让序号整体错位，
   导致**照片与地图张冠李戴**。照片分配（`ASSIGN`）与导览地图（`SPOT_MAP`）
   必须按「**天 + 景点名关键词**」匹配，实际序号从抽取结果现算。
2. **城市前缀正则要写成 `^(城市)(?:[·\s]+|$)`。**
   写成 `^(城市)[·\s]*` 时，`荔波县城` 会被剥成 `县城`，
   再和 `【荔波】` 块就配不上了。必须要求前缀后跟分隔符或正好到结尾。
3. **无 `【】` 表头的散装内容要单独兜住。** 例如某天 I 列直接从 ① 开始写，
   旧解析只取 `📌` 段、把 ①-⑤ 整段丢掉（其中就有还车注意事项）。
   要把「前言块」也并进当日注意事项。
4. **剔除非景点后要跨块去重。** 同一句常同时出现在当日总备注与某个节点块里
   （DAY7 的穿搭就是），不去重会在同一页出现两遍。见 `slides_common.dedup_blocks()`。

### 自检（每次生成后必跑）

- 景点标题里不得出现 `机场 / 车站 / 高铁 / 登机 / 还车 / 中转 / 采购`
- 每个景点都必须配到导览地图与照片（脚本对未命中的键主动告警）
- 收尾页要塞得下：条目多时自动降字号，并确认无裁剪（见 `references/ppt-plans.md`）
- **逐个产物单独回读校验**，不能只查主线：
  `主 HTML` / `单文件版 HTML`（下游快照，改完主 HTML 必须重跑 `inline`）/
  `方案一 PPT` / `方案二 PPT` / `总览 PPT`。
  漏查下游 = 修复只做了一半。
- **全量构建别漏 `--stage 7`**：`build_html.py`、`build_ppt.py` 默认只出 `--stage 1`
  （封面 + 总篇章 + DAY1），漏写会误判成「内容丢了」。
- 回读时用脚本数结构量（`<div class="spot">` 计数、`交通枢纽` 计数），
  别依赖 grep 匹配 emoji —— Git Bash 下 emoji 匹配常失败，误判成「没有」。

## 先对齐，再动手（不可跳步）

**必须先调用 `grill-me` 技能**把决策点问清楚。最少锁死这 6 项：

| # | 决策点 | 为什么必须先定 |
|---|---|---|
| 1 | **线路走向** | 决定总里程、每日车程、候选城市清单 → 直接决定后续所有搜什么、抓什么价 |
| 2 | **往返大交通** | 机票 vs 高铁，人均预算差出几千 |
| 3 | **预算口径** | 节假日真实价 / 平日参考价 / 两套对照 —— 用户常常低估节假日涨幅（实测可达 2.8×） |
| 4 | **交付形态** | 本地 xlsx / 在线文档 / 两者都要 |
| 5 | **每日强度** | 几点出发、日均塞几个景点、日均车程上限 |
| 6 | **采集登录方式** | 见下方「小红书登录」 |

对齐后**开工前**再问一次要不要生成过程文档（任务清单 / 实施计划 / walkthrough / 自测交付），用户可全不选。

## 执行顺序

```
① 读模板表格 → 拿到精确列结构      （腾讯文档 MCP / openpyxl）
② 小红书采集 → .md 正文 + 按 note_id 归档图片   （复用 xhs-humanized-collect 技能）
③ 抓真实报价 → 机票 / 酒店 / 租车              （见 references/scraping-playbook.md）
④ 组装内容   → content.json
⑤ 生成 xlsx  → scripts/build_guide_xlsx.py
⑥ 回读校验   → 逐格检查，重点查中文乱码         （必做，不可省）
⑦ present_files 交付
```

### ① 读模板

用腾讯文档 MCP 读原表结构（列顺序、每个 sheet 的行列坐标）。**物品清单这类静态表要 1:1 复制**，
不要自作主张增删改 item。

注意：腾讯文档连接器**可能中途掉线**。若目标是长期留存的交付物，**优先本地 xlsx**，
在线版让用户自己导入。

### ② 小红书素材

**复用 `xhs-humanized-collect` 技能**，不要重写脚本。它已解决登录、拟人、限速、图片归档。

关键词矩阵设计（覆盖度比数量重要）：
- 大景点名 ×（攻略 / 避坑 / 机位 / 游览顺序）
- 「<目的地> 自驾」「<目的地> 路线图」
- 「<目的地> 美食」「<目的地> 住宿」
- 「<季节/月份> <目的地> 穿衣」「<节假日> <目的地> 人多」
- 「<出发地> 到 <目的地>」（常有同出发地的实操帖，参考价值最高）

产出后跑 `scripts/make_xhs_index.py` 生成 `INDEX.md`，让图片归属可按帖子 ID 反查。

### ③ 抓价

详见 **`references/scraping-playbook.md`**。核心三条：

- **携程机票**必须用「原生 Chrome 启动 + CDP 连接」，直接 Playwright 会被 `whaleguard block`
- **携程酒店**城市下拉的 cityId 很难点进去，抓取成功率低 → 提前准备好降级方案并在交付时如实说明
- **神州租车官网**基本抓不到（PC 端 URL 失效、移动端空壳）→ 用官方公开价目算，必须标注口径

### ④⑤⑥ 组装 / 生成 / 校验

按 **`references/column-rules.md`** 的九列规则填内容。

生成脚本用法：

```bash
python scripts/build_guide_xlsx.py content.json output.xlsx
```

`content.json` 结构见 `examples/guizhou_content_sample.json`（贵州 7 天 6 晚实例，可直接抄结构）。

**回读校验是硬要求。** LLM 生成大段中文行程内容时会产生乱码
（实测出现「黄樹果」「9 点点开」「枪枪安全套退退上下」这类无意义串），
写入时看不出来，**必须重新打开文件逐格读回**。校验要点：

- 每个单元格非空（尤其容易漏 E 列机位、I 列注意事项）
- 地名一致性：全文同一个景点不能出现两种写法
- 乱码扫描：对已知高频错字做子串匹配
- 数字自洽：分项加总 == 合计

## 第二阶段：图文路书（HTML / PPT / PDF）

攻略表做完了，用户常常接着要「图文并茂的路书」。**完整流程、硬约束、踩坑表见
`references/roadbook.md`**；**两套 PPT 的页序、栅格与排版铁律见 `references/ppt-plans.md`**。
这里只列要点：

- **数据流单向**：`攻略.xlsx → content.json / slides.json → HTML / PPT / PDF`。
  改内容改前两级，模板不动。
- **共用一套脚本**：`roadbook_extract_content.py` → `roadbook_build_html.py` →
  `roadbook_print_pdf.py` / `roadbook_build_ppt.py` / `roadbook_inline_html.py`。
- **PDF 由同一份 HTML 打印**，绝不另写一套模板（否则版式必然漂移）。
- **地图必须走官方服务并保留审图号**，禁止 AI 自绘中国地图轮廓。
- **每张实拍图标注来源**（`📷 小红书 @作者 · 帖子ID`）。
- **HTML 要留编辑接口**：`data-edit` 属性 + 编辑模式开关 + 导出 JSON。
- **PPT 交付前必须确认无裁剪/溢出，issues 归零**。
- **先出「封面 + 总篇章 + DAY1」给用户确认排版与内容，再全量出剩余天数**。
- 单文件版 HTML（图片 base64 内嵌）用于直接转发给同行队友。

### 两套 PPT（方案一 / 方案二）

同一份 `slides.json` 出两套，**共用前 4 页与后 2 页**（由 `slides_common` 的
`head_slides()` / `tail_slides()` 提供，两套逐字节一致）：

| | 方案一 · 详细版 | 方案二 · 简洁版 |
|---|---|---|
| 逐日结构 | 当天行程页 + 每大景点 2 页 + 当天收尾页 | **每天固定 2 页**：今日行程 + 今日吃住 |
| 页数（7 天 12 景点） | 44 页 | 20 页 |
| 构建 | `build_ppt_detail.py` | `build_ppt_simple.py` |

**收尾两页是硬要求（用户明确指定，两套都要有）：**

- **次尾页 = 物品清单**（7 个分组，1:1 照抄源表，不增删）
- **尾页 = 结束祝福**（「祝大家旅行顺利」+ 日期/环线/里程 + 关键词 chips）

**逐日页必须装得下**：条目多时先自动收字号兜底，但**不允许出现
`⚠️ 仍差 Npx`**（那意味着内容被静默裁掉）。排版前先量真实内容高度，
flex 用内容自适应基准而不是写死配比 —— 细节与实测数字见 `references/ppt-plans.md`。

## 交付清单

- `攻略.xlsx` —— 5 个 sheet：全部行程 / 人均预算 / 费用明细（只留模板）/ 物品清单（1:1）/ 景点地图
- `xhs_data/` —— notes/*.md + images/<note_id>/*.png + INDEX.md
- （第二阶段）`roadbook/` —— 路书 HTML（含单文件版）+ PDF + `assets/`（地图与压缩后的实拍图）
  + **两套 PPTX**：`..._详细版.pptx`（方案一）、`..._简洁版.pptx`（方案二）
- 验收图 —— 逐页联络表（缩略图 + 页名）方便快速核对，如 `review/sheet_all.jpg`
- 口头说明：哪些价格是真抓的、哪些是估算的、时效性如何

## 硬约束

- **机场 / 火车站 / 高铁站 / 汽车站 / 码头 / 取还车点 / 中转站 / 特产采购
  这类「非景点块」都不是景点**，不得写成 `【景点】`，不得生成景点页
  （详见上方专节）。这一条**贯穿 xlsx → HTML → PPT**，
  任何一层单独"打补丁"都不算修好。
- **两套 PPT 都必须有「次尾页物品清单 + 尾页结束祝福」**，缺页算未完成。
- **逐日页不允许内容被静默裁掉**：构建日志出现 `⚠️ 仍差 Npx` 就必须改排版或删内容。
- **攻略必须给出人均总预算**，且注明计价口径（几人同行、房/车如何摊、含不含往返大交通）
- 用户明确说「费用明细只保留模板」时，**数值一律留空**，不要好心替他填
- 用户明确说「最终住宿后续再来确定」时，酒店列必须原样带上这句备注
- 租车若用户指定了车型档位和保险档位，**保险费用必须单独计入预算**，不能只报裸车租金
- 价格都要标来源与抓取日期；抓不到的如实说，不要用臆测数字冒充实时价
